Build a Resume Update System with Claude

Five stages, run in order. You end up with an assistant that grades resumes like a strict ATS, tailors them to a specific job without inventing anything, and logs every application to your tracker. The order is the lesson: build the knowledge first, the automation last.

How it works

The whole system on one page. Follow the numbers.

Start with the experience bank, not the grader. A grader with no source of truth rewrites bullets from whatever resume you attach. Its edits come out generic, it overstretches stories, and you spend every session correcting its phrasing. When Claude can see the full, confirmed version of every story, it knows what's true and how far a story can be pushed toward a given role.

The build sequence

  1. 1

    Build the master experience bank

    foundation

    One document that holds every true thing you could put on a resume. It is raw material to draw from, not a resume you'd send.

    Show detailsHide details
    Gather
    • Every past resume version, including the ones tailored to specific roles
    • Interview stories (STAR/CARL notes), performance reviews, awards
    • Project write-ups and internship deliverables
    Structure each achievement as
    • Ground truth: what actually happened, the real numbers, your actual role
    • Framings: every version you've used, tagged by target role (product, program, ops…)
    • Guardrails: what you can't claim (targets vs. results, confidential figures)
    Done whenDuplicates are merged, conflicting numbers and dates are settled with you, and every metric has a story behind it.
    Starter prompt
    Build me a master experience bank from all the resumes and stories I've shared. Group every bullet by role and achievement. For each achievement, give the ground-truth story, list every framing I've used and tag it by role type, and flag anything that conflicts across versions (numbers, dates, titles) so I can pick the true one. Don't write a resume. This is a source-of-truth document.
    Why firstEvery later stage pulls from this document. If it's weak, every tailored resume is weak and you end up fixing the same bullets by hand over and over.
  2. 2

    Define "what good looks like"

    the standard

    Write down the rules once, in one place, so every grade and edit gets checked against the same bar.

    Show detailsHide details
    Reference material
    • A guide with examples of strong resumes (a Notion page works well)
    • An approved action-verb list
    Bullet rules
    • Action → Context → Result on every bullet
    • One lead verb per bullet, never repeated anywhere on the resume
    • No two bullets proving the same skill; one line each; one page total
    Done whenSomeone else could grade a resume against your rules and land on the same verdict you would.
    TipKeep personal style rules (banned words, how you title a role) in the same list. Rules copied into several places drift apart.
  3. 3

    Build the grader

    first automation

    Start with the grader as instructions in a Claude Project so it's quick to tune. Once its output stops surprising you, turn it into a skill.

    Show detailsHide details
    What it outputs
    • A strict grade with a one-line reason
    • The 2 highest-ROI edits, each as before → after
    • A short list of flags: bullets missing ACR, repeated verbs, bullets that overlap
    Hard rules
    • Replacement bullets come from the bank only
    • Never fabricate a metric
    • When a job description is given, grade keyword match against it
    Starter prompt
    Act as a strict ATS. Grade the attached resume against my standards doc and verb list. Give an overall grade, then the 2 edits with the highest ROI as before → after. Then flag bullets that break Action-Context-Result, reuse a lead verb, or repeat the same evidence. Pull every replacement from my experience bank. Never invent numbers.
    TipKeep the output short. You want a signal you can act on, not a line-by-line rewrite. Ask for the full pass only when you need it.
  4. 4

    Close the feedback loop

    control loop

    Every correction you make is data. Sort it into the right place so you never have to make the same correction twice.

    Show detailsHide details
    When you correct Claude, ask
    • Is it a fact? ("it was 5 of 8, not all 8") → update the bank and mark it confirmed
    • Is it a style rule? ("never use that verb") → add it to the standard
    • Is it a one-off? → leave it in the chat
    Also write back
    • The latest approved phrasing for each story
    • Standing conventions: date formats, how a title reads on different resumes
    Why it mattersThis loop is what makes the system get better over time. Without it, every session starts over.
  5. 5

    Automate the application pipeline

    end-to-end skill

    Wrap the grader in a skill that runs from a single job description and base resume to a finished resume and a logged application, with you approving at the two points that matter.

    Show detailsHide details
    Steps
    • Start from the job description plus a base resume, ideally your closest past version for that type of role
    • Save the job description as a PDF (postings get taken down)
    • File it in a folder for that company
    • Run the grader, plus a pass that lists the JD requirements you cover and the ones you don't
    • Gate: you approve which edits to make
    • Build an editable resume and check it's one page with no wrapped bullets
    • Gate: you approve the tracker entry, then it's logged in Notion
    Tracker setup (Notion)
    • Companies database: name, industry, careers page
    • Applications database: role, status, date, source, link to the company
    • Keep the files on your computer and link to them from the tracker
    • An interview stories database, which feeds back into the bank
    Guardrails to build inFlag requirements you don't meet instead of stretching to cover them. Ask before adding any tool or skill you haven't confirmed. Never overwrite a resume you've edited by hand.

Pitfalls to avoid

Grader before bankYou'll get generic edits and spend every session correcting phrasing. Build the bank first, even a rough one.
More than one copy of the truthKeep exactly one bank and one rules list. When you revise a doc, replace it. Don't save a new copy next to the old one.
Reusing old framingsTailor from the ground-truth story every time. Rewording an old tailored bullet produces near-duplicate resumes.
Claiming targets as resultsTag each number in the bank as either a measured outcome or a goal. Only measured outcomes go on a resume as results.
Automating too earlyGet the grader's output right in a Project before you turn it into a skill, and turn it into a skill before you chain it into a pipeline.
Unscreened sensitive infoMark confidential figures and internal names in the bank so they never make it into a resume.

Setup options: Google Drive or Notion

Same flow as the overview at the top, with each piece placed in the tool you use.

Which to pick? Choose Drive if you want everything in one place and a spreadsheet tracker. Choose Notion if you already use it, or you want linked databases and board views of your pipeline.
